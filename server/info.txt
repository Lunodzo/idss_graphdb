IDSS Energy Community Query Reference

Run peers from this directory:
  ./start_peers.sh 3
  ./start_peers.sh 3 1

The optional second argument identifies the manager peer. Use the first peer address in logs with the client.

Traversal syntax:
  <source role>:<relationship kind>:<destination role>:<destination kind>

Energy-community node kinds:
  Customer, UsagePoint, EndDevice, GeneratingUnit, BatteryUnit,
  MeterReading, Offer, Bid, Trade

Relationships:
  owns, records, memberOf, places, matches

Queries:
  get Customer
  get Customer traverse owner:owns:asset:UsagePoint
  get Customer traverse owner:owns:asset:UsagePoint traverse point:records:reading:MeterReading
  get MeterReading where readingType = "activePower"
  get Offer where status = "open"
  get Trade

Aggregates:
  get MeterReading where readingType = "activePower" show @sum(value)
  get MeterReading where readingType = "activePower" show @avg(value)
  get MeterReading where readingType = "activePower" show @min(value)
  get MeterReading where readingType = "activePower" show @max(value)

Requester roles are supplied by the client:
  go run . -role member -s <server_multiaddress>
  go run . -role manager -s <server_multiaddress>
  go run . -role observer -s <server_multiaddress>

Manager-only settlement compilation:
  settle <from RFC3339> <to RFC3339>, 10

Local-only queries append -l. The add, update, and delete operations are always local and are not broadcast.
